# Interval DP

[Problem](https://atcoder.jp/contests/dp/tasks/dp_n)
## Solution 
The most important observation is that after every merge, the relative order of the slimes never changes. Since we are only allowed to merge adjacent slimes, every slime that exists at any moment corresponds to some contiguous interval of the original array. This immediately suggests that the problem is about intervals rather than individual elements. A greedy strategy is difficult to justify because a merge affects all future costs. Choosing the cheapest adjacent pair now may create a very large slime that becomes expensive to merge later. Therefore, we need a dynamic programming approach that considers all possible ways of dividing an interval.

To build the DP, think about the final operation. Suppose we want to merge all slimes in the interval [l,r] into a single slime. In the last step, this final slime must have been formed by merging two already-combined groups. There must exist some position m such that the left group contains slimes [l,m] and the right group contains slimes [m+1,r]. Before the last merge happens, both groups must already have been merged optimally into single slimes. This gives us a natural subproblem structure.

Let dp[l][r] denote the minimum cost required to merge all slimes from position l to position r into one slime. If l == r, there is only one slime, so no merge is needed and the cost is zero. For a larger interval, we try every possible split point m between l and r-1. If we choose m as the last split, then the total cost consists of three parts. First, the cost to merge the left interval [l,m]. Second, the cost to merge the right interval [m+1,r]. Third, after both sides become single slimes, we must merge those two slimes together. The size of the resulting merge equals the total size of all slimes in [l,r], so this final merge contributes sum(l,r) to the cost.

Therefore the recurrence becomes
dp[l][r]
=
min(
    dp[l][m]
    +
    dp[m+1][r]
    +
    sum(l,r)
)

for every valid split point m.

To evaluate sum(l,r) efficiently, we use prefix sums. Let
pref[i] = a[1] + a[2] + ... + a[i]
Then the total size of any interval can be computed in constant time as
sum(l,r) = pref[r] - pref[l-1].

Without prefix sums, we would have to repeatedly sum intervals, making the solution much slower.

The DP can be computed either recursively with memoization or iteratively by interval length. In the iterative version, we first solve intervals of length 1, then length 2, then length 3, and so on. When computing an interval [l,r], all smaller intervals required by the recurrence have already been computed. For each interval we try every possible split point, update the minimum cost, and store the result in dp[l][r].

There are O(N²) interval states because every state is defined by a pair (l,r). For each state, we try up to O(N) split points. Therefore the total time complexity is O(N³). With N ≤ 400, this complexity is acceptable for the intended solution. The memory complexity is O(N²) for storing the DP table.

The final answer is dp[1][N], which represents the minimum cost required to merge all slimes into a single slime. The key insight is that the last merge partitions the interval into two smaller independent intervals, making interval DP the natural and optimal approach for this problem.

## Recursive code 
```cpp
#include <bits/stdc++.h>
using namespace std;

#ifndef ONLINE_JUDGE
#include "trace.cpp"
#else
#define dbg(...)
#endif
#define int long long

const int inf = 1e18;
const int mx = 400 + 12;
int dp[mx][mx];
vector<int> v, pre;
int n;

int yo(int l, int r) {

    if (l == r) return 0;
    if (dp[l][r] != -1) return dp[l][r];

    int ans = inf;
    int sum = pre[r] - pre[l - 1];
    for (int mid = l; mid < r; mid++) {

        int left = yo(l, mid);
        int right = yo(mid + 1, r);
        ans = min(ans, left + right + sum);
    }
    return dp[l][r] = ans;
}

void solve() {

    cin >> n;
    v.resize(n + 1);
    pre.resize(n + 1);
    pre[0] = 0;
    for (int i = 1; i <= n; i++) {
        cin >> v[i];
        pre[i] = pre[i - 1] + v[i];
    }
    memset(dp, -1, sizeof(dp));
    cout << yo(1, n) << '\n';
}

int32_t main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);
    
    int tests = 1;
    // cin >> tests;
    for (int tc = 1; tc <= tests; tc++) {
        solve();
    }
    return 0;
}
```

## Iterative Code 
```cpp
#include <bits/stdc++.h>
using namespace std;

#ifndef ONLINE_JUDGE
#include "trace.cpp"
#else
#define dbg(...)
#endif

const int inf = 1e18; 

void solve() {
    int n ; cin >> n ;
    vector<int> v(n+1) , pre(n+1,0);
    for ( int i = 1 ; i <= n ; i++ ){
        cin >> v[i];
        pre[i] = pre[i-1] + v[i];
    }
    vector<vector<int>> dp(n+1 , vector<int> (n+1, inf));
    for (int i = 1; i <= n; i++) {
        dp[i][i] = 0;
    }

    for ( int len = 2 ; len <= n ; len++ ){
        for ( int l = 1 ; l+len-1 <= n ; l++ ){ // like window with lenght len
            int r = l + len-1; 
            int sum = pre[r] - pre[l-1];
            for ( int mid = l ; mid < r ; mid++ ){
                dp[l][r] = min( dp[l][r] , dp[l][mid]+dp[mid+1][r]+sum);
            }
        }
    }

    cout << dp[1][n] << '\n';

}

int32_t main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);
    
    int tests = 1;
    // cin >> tests;
    for (int tc = 1; tc <= tests; tc++) {
        solve();
    }
    return 0;
}
```
